# 安全与隐私规范

> Status: Proposed<br>
> Owner: 角色 B<br>
> Reviewers: 角色 A<br>
> Last Updated: 2026-08-12

## 1. 范围

TeamUp 处理学生资料、项目经历、合作偏好、私信和微信登录身份，属于需要谨慎保护的用户数据。本文件是工程最低要求，不替代正式法律审查和上线平台规则核验。

## 2. 数据最小化

- 每个字段都要说明目的、是否必需、可见范围和保留期限；
- 首版不收集身份证、精确住址、通讯录和与组队无关的信息；
- 联系方式默认不公开，优先站内沟通；
- 院校、经历和时间偏好由用户主动填写并可修改；
- 埋点不发送消息正文、令牌、微信身份标识或完整个人简介。

## 3. 同意与用户权利

- 首次处理个人信息前展示隐私政策和服务条款版本；
- 非必要信息和 AI 数据使用应有单独、清晰说明；
- 用户可查看、更正、撤回公开、申请导出和注销；
- 注销流程说明保留/删除/匿名化范围、处理时间和例外；
- 隐私政策改变时记录版本和重新同意策略。

## 4. 认证与会话

- 微信登录凭证只发送给服务端，并按一次性凭证处理；
- 微信密钥和会话签名密钥不进入客户端、仓库和日志；
- 访问凭证设置有效期、撤销能力和安全存储策略；
- 敏感操作要求有效会话，必要时重新验证；
- 登录、撤销和异常失败进行限流与安全审计。

## 5. 授权

所有授权在服务端执行：

- 用户只能编辑自己的资料；
- 项目创建者只能管理自己的项目和岗位；
- 只有会话参与者能读取消息；
- 邀请接受者必须是当前登录用户；
- 管理权限独立分配并记录审计；
- 每个对象接口测试 IDOR/越权场景，不能只隐藏前端入口。

资源不存在与无权访问的响应应避免泄露敏感资源是否存在。

## 6. 输入、内容与上传

- 服务端校验类型、长度、枚举、状态和业务关系；
- 富文本若引入必须使用允许列表清洗，默认使用纯文本；
- 防范 SQL 注入、XSS、命令注入和不安全反序列化；
- 上传能力启用前，限制类型、大小、数量，使用随机对象名和隔离域名，并进行恶意内容检测；
- 用户生成内容提供举报、拉黑、下架和申诉/复核路径。

## 7. AI 安全

- 自训练推荐模型只能使用经过评审的结构化特征和合规事件；
- 训练集、特征、标签和模型版本必须可追溯，用户注销/撤回同意和保留政策应覆盖派生数据；
- 机器学习模型不能绕过规则层的权限、拉黑、项目状态、容量和必需条件；
- 禁止使用学校层级、性别、民族、家庭背景、私信正文、举报原文等敏感或代理特征；
- 模型上线前检查时间泄漏、位置偏差、分组效果、异常输出和规则回退；
- 大模型只接收完成任务需要的最小数据；默认不传私信、联系方式和第三方隐私；
- 提示词中的用户内容视为不可信，不允许其覆盖系统规则或触发工具权限；
- AI 输出做 schema、长度和内容校验；涉及用户资料必须由用户确认；
- 不用生成式 AI 或推荐模型自动执行封禁、信誉处罚、成员录取或履历认证；
- 记录供应商、模型、区域、保留策略和数据使用条款，确认后才可进入生产；
- 提供功能开关、频率/费用上限、超时和非 AI 降级。

## 8. 密钥与配置

- 密钥通过环境变量或云密钥服务注入；
- `.env.example` 只包含变量名和安全占位值；
- 权限按环境和服务最小化，禁止共享生产管理员凭证；
- 密钥定期轮换；疑似泄漏时立即撤销并轮换，不能只删除 Git 文件；
- CI、日志、错误跟踪和截图中也不得暴露密钥。

## 9. 日志与审计

任务分支已为 `REPORT_SUBMITTED` 和 `ACCOUNT_DELETION_REQUESTED` 增加数据库审计事件，记录 actor、动作、资源、服务端校验后的 request ID、结果和时间；幂等重试不重复写入。当前不提供普通用户读取接口，管理员审计查询与保留策略仍待治理权限和隐私评审。

允许记录：请求 ID、匿名/内部用户 ID、动作、资源 ID、结果、错误码、耗时和时间。

任务分支的 HTTP 完成日志进一步限制为结构化 `event`、request ID、method、path、status 和 durationMs；query string、Authorization、请求体和响应正文不写入日志。客户端 request ID 仅接受 `[A-Za-z0-9._:-]+` 且最长 128 字符，否则由服务端重新生成。

禁止记录：访问令牌、第三方登录凭证、密钥、完整私信、完整未公开简介、上传证明原文和数据库连接串。

高风险操作应审计：管理员登录、内容下架、账号暂停、权限变化、数据导出、注销处理和密钥配置变化。

## 10. 数据保护与保留

- 传输使用 TLS；生产数据库、备份和对象存储启用适当加密与访问控制；
- 备份访问权限与生产数据同等级保护，并定期验证恢复；
- 定义消息、举报、审计、已关闭项目和已注销用户数据的保留期限；
- 测试和本地环境禁止使用未经匿名化的生产数据；
- 第三方供应商仅获得必要数据并接受供应商风险评估。

## 11. 滥用防护

实现状态：用户拉黑堆叠分支已实现拉黑/取消拉黑和双向内部查询；后续成员、邀请及会话消息分支分别接入新成员、新邀请/接受、新会话/新消息阻断。上述分支尚未合入 `main`，发现和匹配仍未接入；后续模块必须调用同一服务端查询，不能依赖客户端缓存或按钮状态。消息只有参与者可读取或发送，非参与者按不可见资源返回；拉黑不删除历史正文，且正文不得进入应用日志、推荐特征或训练数据。

- 登录、搜索、发消息、邀请、举报和 AI 调用分别限流；
- 防止批量爬取公开名片，列表限制字段和分页上限；
- 对重复骚扰、恶意邀请和举报滥用建立检测与人工复核；
- 拉黑后在所有发现、消息和邀请路径统一生效；
- 安全措施不能通过返回过多错误细节泄露内部规则。

## 12. 上线前安全门槛

### 限流实现（Confirmed）

- 登录、举报、邀请和消息发送入口使用服务端固定窗口限流，命中时返回 `429 RATE_LIMITED` 与 `Retry-After`。
- 当前实现为单进程内存计数器，适用于本地、测试和单实例部署；多实例生产环境必须在接受共享限流架构决策后接入共享存储。
- 限流键不采信客户端自报的代理头：登录使用服务端连接地址，其他入口使用已鉴权用户标识。

- 完成威胁建模和数据字段清单；
- 通过认证、资源级授权、输入校验、限流和敏感日志测试；
- 隐私政策、服务条款、举报、拉黑和注销可用；
- 依赖漏洞和密钥扫描无未处理高危项；
- 备份恢复和安全事件联系人明确；
- 生产 AI 数据流、供应商和关闭开关经过双方确认。

安全事件应立即停止扩大影响、保存必要证据、轮换受影响凭证、评估用户影响并按适用要求处置。不得在不理解影响前删除日志或掩盖事件。
