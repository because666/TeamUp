## 1. 目标

改善微信小程序 P0 名片、项目岗位、联系中心和工作台的视觉层级、触控反馈与移动端排版，并完成双方同意后交换联系方式及项目邀请处理闭环。

## 2. 依据

- PRD：`PROF-001`、`PROJ-001`、`CONTACT-001`、`TEAM-001`、`NFR-COMP-001`；`MSG-001` 已 Deprecated
- API：项目详情复用 `API-PROJ-02`；联系方式交换使用 `API-CONTACT-CARD-01/02`、`API-CONTACT-REQ-01..05`；项目邀请列表/处理使用 `API-TEAM-02/03/04`
- ADR：N/A

## 3. 范围

- 更新 `apps/miniapp` 的全局视觉 token、页面布局和可复用控件样式；
- 覆盖能力标签、场景/角色选择、步进器、确认弹窗、空状态和工作台快捷入口；
- 根据角色 A 验收反馈，将工作台名片/项目操作固定到行尾，并补齐发现卡片到公共项目详情的路由；
- 保持 fixture/API 模式；公共详情经 repository 读取，真实模式复用 `API-PROJ-02`；
- 在开放岗位卡片提供联系方式交换入口，双方明确同意后才返回并复制对方的微信号、QQ 或邮箱；
- 一级“联系”使用“联系方式 / 项目邀请”分段，并在每类中按“收到 / 发出”查看和处理；
- 角色 A 跨职责补充内存/MySQL 联系交换和邀请列表实现；角色 B 必须复核 API、迁移、安全、并发和构建结果。

## 4. 非目标

- 不新增广告 SDK、广告位、埋点、接口或数据库字段；
- 不改变匹配、登录、发布、隐私或权限行为；
- 不以 H5 预览代替微信开发者工具和真机验收。

## 5. 依赖与假设

- 基线为 P0 集成提交 `a8d90c4`，当前仍未合入 `main`；
- 以微信小程序窄屏触控为优先，H5 仅用于快速视觉验证；
- 商业化广告后续作为独立产品/合规任务处理，不在本任务预埋实现细节。

视觉参考：

- <https://detail.design/detail/respect-platform-language>：使用微信小程序熟悉的平台语言和克制反馈；
- <https://detail.design/detail/describe-link-action>：按钮明确描述“申请交换”“接受邀请”等动作结果；
- <https://detail.design/detail/visual-alignment-for-buttons-with-icon>：图标与文字在固定触控尺寸内视觉对齐。
