## 1. 目标

实现已确认的 `match-v0.1` 确定性规则引擎，为双向匹配提供版本化分数、置信度、内部排序分和结构化解释。

## 2. 依据

- ADR：[ADR-0002](../../decisions/ADR-0002-mvp-ai-scope.md)
- 规则：[MATCHING.md](../../architecture/MATCHING.md)
- 后端需求：`BE-GOAL-004`、`BE-MATCH-001/002`、`BE-E2E-005`
- API：`API-MATCH-01/02` 的 `MatchResult` 最小字段

## 3. 范围

- 硬约束结果与安全概括原因；
- 技能、方向、时间、专业、经历和合作偏好六项加权；
- 缺失数据重归一化、置信度惩罚和稳定规则版本；
- 结构化 factor/reason code；
- golden、边界、缺失信息和确定性测试；
- 匹配规范和任务证据同步。

## 4. 非目标

- 本任务不实现 P1 机器学习模型；
- 不使用通用大模型、embedding 或向量数据库打分；
- 不在字段契约未确认前猜测经历、时间段、required skill、容量或拉黑的物理数据；
- 不在 API 列表信封、分页和 recommendation request 签发位置确认前发布新端点；
- 不实现曝光、消息、邀请或成员模块。

## 5. 已确认规则

- 权重：技能 35、方向 20、时间 20、专业 10、经历 10、合作偏好 5；
- `rawScore` 按可用因素权重重归一化；
- `confidence = availableWeight / 100`；
- `rankingScore = rawScore * (0.7 + 0.3 * confidence)`；
- `confidence < 0.60` 时必须标记信息不足；
- 引擎版本为 `match-v0.1`，相同输入必须得到相同结果。

## 8. 当前字段缺口

| Gap | 当前状态 | 影响 |
| --- | --- | --- |
| required/bonus skill | 岗位只有无类型技能列表 | 暂不能把某个技能静默当作硬门槛 |
| 技能标准词与别名 | 尚无版本化词表 | 引擎只对上游提供的规范化标签做大小写和空白归一化 |
| 用户方向偏好 | 名片没有独立方向字段 | 方向因素必须显式缺失 |
| 时间段 | 只有每周小时数 | 可算投入量，不能判断时间段完全冲突 |
| 经历 | 尚无持久化实体 | 经历因素必须显式缺失 |
| 拉黑/容量/成员 | 模块尚未实现 | 端点候选过滤不能宣称完整 |
