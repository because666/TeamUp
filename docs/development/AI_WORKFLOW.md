# 双人 Codex 协作流程

> Status: Proposed<br>
> Owner: 角色 A / 角色 B<br>
> Last Updated: 2026-08-10

## 1. 目标

本流程用于避免两个成员分别使用 Codex 时出现范围漂移、重复实现、覆盖文件、接口不一致、虚报测试和状态失联。根目录 [AGENTS.md](../../AGENTS.md) 是强制规则，本文件定义具体操作方式。

## 2. 一次会话只承担一个任务合同

向 Codex 下达任务时至少包含：

```text
任务 ID：TUP-xxx
负责人：角色 A / 角色 B
目标：用户可观察到的结果
范围：允许修改的模块或文件
非目标：明确不做的内容
依据：PRD/API/ADR 链接或需求 ID
验收：必须通过的场景和命令
交付：代码、测试、文档、状态文件
是否允许 commit/push：否（默认）/ 是（明确写出）
```

如果任务会影响另一角色的职责范围，合同还要写明评审人和契约先行要求。

## 3. Codex 标准阶段

### 阶段 A：Inspect

- 读取根 `AGENTS.md`、`CURRENT.md`、任务文件和相关规范；
- 检查 Git 分支、未提交改动和远程基线；
- 阅读现有实现和测试，不按文件名猜行为；
- 输出发现的约束、冲突和假设。

### 阶段 B：Plan

- 把工作拆成可验证步骤；
- 标出公共 API、数据、权限、依赖和文档影响；
- 重大未决项通过 ADR/用户确认，不自行选择；
- 更新任务文件的计划和基线。

### 阶段 C：Implement

- 只做任务合同范围内的最小完整实现；
- 保留他人改动，不做无关格式化；
- 行为与测试同步；公共契约先更新；
- 发现范围扩大时暂停并更新合同，而不是继续扩张。

### 阶段 D：Validate

- 运行相关测试、静态检查和构建；
- 检查权限失败、空状态、重复请求和外部服务失败；
- 复查 `git diff`、文档链接和敏感信息；
- 只记录实际执行结果。

### 阶段 E：Handoff

- 更新任务状态、最后提交、验证证据和剩余风险；
- 需要另一角色继续时创建交接记录；
- 明确未运行的检查和原因；
- 未被明确授权时停在未提交或本地提交状态，不 push/merge/deploy。

## 4. 文件同步模型

```text
main/CURRENT.md           = 已合并状态快照
feature/task-file.md      = 单个任务的实时状态，由唯一负责人编辑
docs/decisions/*.md       = 跨会话长期决策
API/OpenAPI + DATA_MODEL  = 前后端共享契约
Git commit/PR             = 可复现的实现与评审记录
聊天消息                  = 临时沟通，不是项目真值
```

禁止让两个 AI 同时更新同一个任务文件或共享契约。需要并行时拆分为不同文件/模块，并指定一个集成任务。

## 5. AI 必须停止并确认的情况

- 需要选择或切换后端框架、数据库、云服务或生产 AI 供应商；
- 需要新增生产依赖但现有依赖可行性尚未评估；
- 需要修改公共 API、数据库 schema、权限模型、匹配权重或隐私策略；
- 需求文档互相冲突且选择会影响用户行为；
- 发现不属于当前任务的用户未提交修改；
- 需要删除数据、重写 Git 历史、强制推送、部署或操作生产环境；
- 测试失败原因不明，继续修改可能掩盖现有缺陷。

## 6. AI 禁止行为

- 根据常见项目模板假装目录、命令、接口或依赖已经存在；
- 将“测试未运行”写成“测试通过”；
- 为了让测试绿而删除断言、跳过测试或吞异常；
- 用 mock 成功响应掩盖未完成后端；
- 在前端实现服务端权限或信任客户端所有者字段；
- 自动修改 `AGENTS.md` 来给自己扩大权限；
- 把临时聊天决定当作长期共识而不写 ADR/任务记录；
- 读取或输出 `.env`、密钥、令牌和真实用户隐私数据；
- 未经授权执行 commit、push、merge、release 或 deploy。

## 7. 推荐提示词

### 角色 A 功能任务

```text
按仓库 AGENTS.md 执行 TUP-xxx。负责人是角色 A。
实现 PRD <ID> 的前端/产品部分，修改范围是 <paths>。
后端契约以 docs/architecture/API_CONTRACT.md 为准；缺失字段先提出契约变更，不自行发明。
完成对应测试、文档和任务状态，不 commit、不 push。
```

### 角色 B 接口任务

```text
按仓库 AGENTS.md 执行 TUP-xxx。负责人是角色 B。
实现 PRD <ID> 和 API <ID>，修改范围是 <paths>。
重点验证资源级授权、幂等、事务、错误码和日志脱敏。
完成迁移、测试、契约和任务状态，不 commit、不 push。
```

### 代码评审

```text
按 AGENTS.md 的 Code Review Rules 审查当前分支相对 origin/main 的差异。
只做评审，不修改文件。优先报告安全、数据、接口和需求回归，给出文件与行号；说明测试缺口。
```

## 8. 会话恢复

新的 Codex 会话不得只依赖用户一句“继续”。恢复顺序：

1. 检查当前分支和工作区；
2. 读取任务文件的基线、最后进展和验证记录；
3. 查看相对 `origin/main` 的提交与 diff；
4. 复核未决问题是否已有新 ADR/评审结论；
5. 从任务文件“下一步”继续，并先验证现状。

## 9. 规则维护

根 `AGENTS.md` 只保留稳定、强制、跨模块规则。具体技术命令写到相应子目录 `AGENTS.md` 或开发文档。修改 AI 规则需要双方评审，并在 PR 中说明防止了什么实际风险。

官方 Codex 指令发现规则：<https://learn.chatgpt.com/docs/agent-configuration/agents-md>。
