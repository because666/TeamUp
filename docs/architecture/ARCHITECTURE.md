# TeamUp 系统架构

> Status: Proposed<br>
> Owner: 角色 B<br>
> Reviewers: 角色 A<br>
> Last Updated: 2026-08-10

## 1. 架构目标

- 用最少的基础设施支撑 MVP 真实上线与试点；
- 让前端、后端和 AI 能通过稳定契约并行开发；
- 关键写操作可追踪、可恢复，权限在服务端统一执行；
- AI 和第三方服务失败时不影响基础组队闭环；
- 只有在真实负载和数据证明需要时才拆服务或增加搜索集群。

## 3. 推荐总体结构

首版推荐“模块化单体 + 单一事务数据库”，而不是过早拆微服务。

```text
UniApp 微信小程序
        |
        | HTTPS / JSON / API v1
        v
后端应用
  |- Auth：登录、会话、权限
  |- Profile：能力名片与公开设置
  |- Project：项目、岗位、成员
  |- Discovery：筛选与分页
  |- Matching：硬约束、规则排序、模型重排、版本与解释因子
  |- Messaging：会话、消息、邀请
  |- Moderation：举报、拉黑、内容状态
  |- Recommendation Training（离线）：数据集、训练、评估、模型登记
  |- AI Gateway（可选）：生成式文案、脱敏、限流、降级
        |
        +---- MySQL（权威业务数据）
        +---- 对象存储（仅在上传能力确认后引入）
        +---- 微信登录接口 / 大模型 API（外部依赖）
```

模块间通过明确的应用服务和领域对象协作，不允许跨模块随意读写内部表。若未来拆服务，API 契约和领域边界应能继续使用。

## 4. 客户端职责

- 页面展示、表单交互、客户端基础校验和加载/错误状态；
- 只保存最少会话信息，不保存第三方密钥；
- 不承担最终权限判断、匹配分数计算或内容安全决定；
- 对网络失败、重复提交和 AI 不可用提供明确反馈；
- 开发阶段可以使用契约生成的 mock，但不得让 mock 结果进入生产配置。

## 5. 后端职责

- 微信凭证交换、平台会话签发和撤销；
- 资源级鉴权、业务规则、幂等和事务边界；
- 个人资料、项目、岗位、匹配、会话和举报数据的权威写入；
- 统一错误码、审计事件和可观测性；
- 对外部服务设置超时、重试上限、限流和降级；
- 保证返回数据已经按可见性和拉黑关系过滤。

## 6. 数据与一致性

- MySQL 是账号、项目、岗位、成员、邀请和消息状态的唯一权威来源。
- 接受邀请必须在单个事务中检查项目/岗位状态、容量、重复成员并写入结果。
- 删除优先采用业务状态与审计策略；个人数据到期后按隐私政策删除或匿名化。
- 缓存、搜索索引和向量索引若后续引入，只能是可重建的派生数据，不能成为唯一事实来源。
- 所有 schema 变化使用版本化迁移，不允许生产环境手工改表后不记录。

## 7. AI 网关边界

所有大模型调用统一经过 AI Gateway：

- 只传任务所需的最小字段，默认不传联系方式、微信身份标识、消息历史和非公开资料；
- 记录模型配置版本、提示模板版本、耗时和结果状态，不记录敏感完整提示；
- 输出先做结构校验和安全过滤，再交给用户确认；
- 设置超时、预算、频率限制、功能开关和模板化降级；
- AI 不直接写入已确认履历、匹配分数、成员关系和处罚结果。

自训练推荐模型不通过 AI Gateway。它由离线训练流程产生版本化模型，只能在服务端重排已通过硬约束的候选；模型不可用、版本不兼容或低置信度时立即回退规则排序。详细流程见 [ML_RECOMMENDER.md](ML_RECOMMENDER.md)。

## 8. 环境

| 环境 | 用途 | 数据规则 |
| --- | --- | --- |
| local | 本地开发与单元测试 | 仅使用假数据或匿名数据 |
| test | 自动化测试/集成验证 | 可重复构建，禁止生产数据 |
| staging | 上线前验收 | 配置接近生产，使用独立账号与数据库 |
| production | 真实用户 | 最小权限、备份、监控和审计 |

环境配置通过环境变量或密钥管理服务注入。仓库只提供不含密钥的 `.env.example`。

## 9. 失败与降级

- 推荐模型失败：回退到相同契约的规则排序并记录降级原因。
- 大模型失败：返回结构化规则/模型解释或允许用户手动填写，不阻断发布和匹配。
- 微信接口失败：不创建半完成会话，返回可重试错误。
- 消息发送重复：使用客户端请求 ID 或幂等键避免重复记录。
- 搜索/推荐失败：降级为最新公开项目和基础数据库筛选。
- 部分响应失败：不得返回伪造数据或空成功；使用稳定错误码和请求 ID。

## 10. 架构变更门槛

以下变更必须先有 Accepted ADR：后端框架、服务拆分、数据库类型、认证方式、搜索/向量基础设施、消息中间件、生产 AI 供应商、部署拓扑和跨境数据处理。
