# 可解释匹配设计

> Status: Proposed<br>
> Owner: 角色 A（规则）/ 角色 B（实现）<br>
> Last Updated: 2026-08-10

## 1. 目标

匹配系统分两阶段：V0.x 用结构化、可重复和可解释的规则完成冷启动；积累合规反馈后，V1.x 使用平台自己训练的轻量机器学习模型重排候选。两者都不是能力高低评价，也不应根据学校、性别等敏感或容易造成不公平的因素决定机会。

本方案需双方确认后才能成为生产规则；任何权重变化都要增加规则版本并保留评估记录。

## 2. 输入

- 用户：公开状态、技能、专业方向、合作偏好、可投入时间、相关经历；
- 项目岗位：状态、必需/加分技能、项目方向、角色偏好、时间要求、经历要求；
- 治理：账号状态、拉黑关系、项目/岗位状态；
- 禁止输入：联系方式、私信内容、举报原文、微信身份标识、无关敏感属性。

## 3. 硬约束过滤

任一条件命中时不进入正常推荐：

- 用户或项目不可见、停用、删除或被下架；
- 项目/岗位未发布、已关闭或已满员；
- 双方存在任一方向拉黑；
- 项目明确标记的必需条件不满足；
- 明确时间要求与用户可用时间完全不重叠；
- 用户明确不接受该合作场景或身份。

被过滤原因只向有权限的一方展示安全、概括的原因，不泄露对方隐私或拉黑细节。

## 4. V0.1 建议权重

| 因素 | 权重 | 说明 |
| --- | ---: | --- |
| 技能适配 | 35 | 必需和加分技能覆盖、熟练度（若可靠） |
| 项目方向 | 20 | 用户意向与项目方向的结构化重合 |
| 时间适配 | 20 | 时间段和每周投入的可行程度 |
| 专业相关 | 10 | 只作为补充信号，不能替代技能证据 |
| 相关经历 | 10 | 赛事/科研/项目类型相关性，区分自述与认证 |
| 合作偏好 | 5 | 队长/队员和合作方式偏好 |

每个可计算因素输出 `0..100` 分。资料缺失不等同于能力为零：

```text
rawScore = sum(weight_i * factorScore_i) / sum(availableWeight_i)
confidence = sum(availableWeight_i) / 100
rankingScore = rawScore * (0.7 + 0.3 * confidence)
```

- 面向用户显示四舍五入后的 `rawScore` 和资料完整度提示；
- 排序内部使用 `rankingScore`，避免资料极少的候选因单项高分占据顶部；
- `confidence < 0.60` 时标记“信息不足”，不显示“高度匹配”；
- 精确阈值和公式属于 Proposed，必须通过样本评估后确认。

## 5. 技能评分建议

- 必需技能先参与硬约束或高权重评分，取决于项目方是否标为 `required`；
- 技能名称先映射到受控词表和别名，不能只做原始字符串相等；
- 自报熟练度只能作为弱信号，认证或可验证经历可提高置信度；
- 不允许通用大模型直接输出最终技能分数；标签归一化候选必须由受控词表、规则或用户确认。

## 6. 解释输出

匹配服务必须返回结构化因素，不依赖大模型才能解释：

- 主要匹配项，例如“覆盖 3 个岗位技能中的 2 个”；
- 需要确认的差异，例如“周末时间尚未填写”；
- 未满足但可协商的条件；
- `engineType`、`engineVersion`、`modelVersion`、`score` 和 `confidence`。

生成式 AI 只能把这些因素转成更自然的文本，不得改变数据或补写理由。

## 7. V1.x 轻量模型重排

- 硬约束过滤和候选生成始终由规则层负责；机器学习只对合法候选重排；
- 训练标签优先使用邀请接受、组队确认等强结果，详情和沟通只作为弱反馈；
- 未曝光候选不能作为负样本，沉默也不能无条件当作拒绝；
- 首个基线模型优先选择逻辑回归等可解释模型；只有离线证据证明收益时再评估 GBDT 或 learning-to-rank；
- 冷启动、数据不足、模型加载失败或特征版本不一致时使用 V0.x 规则结果；
- 详细数据、训练、评估和发布流程见 [ML_RECOMMENDER.md](ML_RECOMMENDER.md)。

## 8. 版本与评估

- 规则版本格式：`match-v0.<minor>`；模型版本格式：`rank-v1.<minor>`；
- 权重、过滤条件、字段含义改变必须升级版本；
- 记录离线样本、预期排序、实际排序和人工判断，不保存不必要的个人信息；
- 试点阶段观察匹配到详情、沟通和接受邀请的漏斗，但不能只用点击率优化；
- 上线前至少覆盖硬约束、缺失资料、同分排序、拉黑、岗位满员和重复计算测试。

## 9. 风险控制

- 不使用学校层级、性别、民族、家庭背景等敏感或代理特征做匹配排序；
- 不把低分解释为用户能力差；
- 用户可修改资料并看到影响匹配的主要因素；
- 项目方不能看到候选人的非公开资料；
- 规则或模型异常时降级为基础筛选与最新列表，不伪造推荐。
