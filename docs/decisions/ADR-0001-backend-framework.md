# ADR-0001: 后端框架选择

> Status: Proposed<br>
> Decision Owner: 角色 B<br>
> Reviewer: 角色 A<br>
> Date: 2026-08-10

## Context

原始文档同时列出 FastAPI 和 Spring Boot，但未做最终选择。框架决定工程布局、语言、依赖管理、测试、部署、OpenAPI 生成和后续维护方式，因此在后端初始化前必须确认。

## Decision Drivers

- 角色 B 的真实熟练度和长期维护能力；
- 两人 + AI 模式下的开发速度与可审查性；
- 类型/参数校验、权限、事务和迁移工具成熟度；
- OpenAPI 契约和前端类型生成体验；
- 腾讯云部署、监控和故障排查成本；
- AI SDK 生态并非唯一标准，P0 业务可靠性优先。

## Option A: FastAPI

优点：

- Python 代码简洁，原型和 AI SDK 集成通常较快；
- 类型模型可生成 OpenAPI，适合契约优先；
- 小团队初期迭代成本较低。

风险：

- 异步、数据库事务、依赖注入和项目结构需要团队统一规范；
- 若角色 B 更熟悉 Java，实际维护优势可能不存在；
- 必须严格锁定依赖、类型检查和迁移工具，避免“动态语言随意写”。

## Option B: Spring Boot

优点：

- 类型、依赖注入、安全、事务和运维生态成熟；
- 复杂业务增长后的组织方式明确；
- 若角色 B 熟悉 Java，长期可靠性和排障更可控。

风险：

- 首版样板和配置可能更多；
- 小团队若不熟悉生态，初始化与迭代成本较高；
- AI 相关 Python 工具若确有需要，未来可能增加额外进程，但首版未必需要。

## Required Spike

角色 B 应用两个候选框架中的首选做一个不超过半天的纵向验证：健康检查、MySQL 连接/迁移、一个受保护 CRUD、OpenAPI、单元与集成测试、容器启动。只在首选验证失败或双方仍有疑问时验证另一个框架。

## Consequences

接受后需要在同一初始化任务和评审批次中：

- 建立 `services/api` 和子目录 `AGENTS.md`；
- 固定运行时和依赖版本；
- 补齐开发、测试和启动命令；
- 建立迁移、OpenAPI、日志、健康检查和 CI 基线；
- 更新 `CURRENT.md`。
