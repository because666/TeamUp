# TeamUp 信息架构

> Status: Proposed<br>
> Owner: 角色 A<br>
> Reviewer: 角色 B（接口、安全与技术可行性）<br>
> Last Updated: 2026-08-10

## 1. 目标

信息架构服务于重复使用的组队工作流：发现项目/成员、处理匹配与沟通、管理自己的资料和项目。首屏直接进入实际使用界面，不设置营销落地页。本文件定义产品页面层级；不锁定 UniApp 版本、路由库或组件库。

## 2. 一级结构

登录后使用四个稳定一级入口：

| Entry | 用户目标 | 默认内容 |
| --- | --- | --- |
| 发现 | 找项目或找队友 | 项目列表；“项目/人才”分段切换 |
| 匹配 | 查看结构化推荐与原因 | 与当前身份相关的项目/成员候选 |
| 消息 | 继续沟通和处理邀请 | 会话列表；邀请作为关联状态展示 |
| 我的 | 管理资料、项目和账户 | 名片摘要、我的项目、设置与安全入口 |

“发布项目”是清晰命令，出现在“发现”和“我的项目”，不占用第五个一级入口。未登录用户触发受保护命令时进入登录流程。

## 3. 页面树

```text
应用启动
├─ S-AUTH-01 登录、服务条款与隐私同意
└─ 登录后主框架
   ├─ 发现
   │  ├─ S-DISC-01 项目/人才列表
   │  ├─ S-PROJ-03 项目详情
   │  └─ S-PROF-02 公开名片详情
   ├─ 匹配
   │  ├─ S-MATCH-01 候选列表
   │  └─ S-MATCH-02 匹配原因详情
   ├─ 消息
   │  ├─ S-MSG-01 会话列表
   │  └─ S-MSG-02 会话详情
   └─ 我的
      ├─ S-ME-01 我的工作台
      ├─ S-PROF-01 能力名片编辑
      ├─ S-PROJ-LIST-01 我的项目
      │  ├─ S-PROJ-01 项目与岗位编辑
      │  ├─ S-PROJ-02 发布预览
      │  └─ S-PROJ-03 发布结果/项目详情
      ├─ S-TEAM-01 邀请与组队记录
      └─ S-SET-01 账户、隐私、拉黑与注销
```

本任务详细定义 `S-AUTH-01`、`S-PROF-01`、`S-ME-01`、`S-PROJ-LIST-01`、`S-PROJ-01/02/03`。其他页面保留稳定 ID，后续任务补充页面规范。

## 5. 权限与可见性

| 用户状态 | 发现公开内容 | 编辑名片 | 创建项目草稿 | 发布项目 | 管理他人项目 |
| --- | --- | --- | --- | --- | --- |
| Guest | TBD，由隐私与运营策略确认 | 登录后 | 登录后 | 否 | 否 |
| 已登录、名片未完成 | 是（若公开浏览允许） | 是 | 是 | 否 | 否 |
| 已登录、名片完成 | 是 | 是 | 是 | 是 | 否 |
| 项目 owner | 是 | 是 | 自己的项目 | 自己且通过校验 | 否 |

前端可根据状态减少无效操作，但服务端必须独立验证会话、资源所有权、项目状态和岗位容量。对无权查看的敏感资源，页面不能通过错误文案泄露资源是否存在。

## 6. 导航规则

- 一级入口切换保留各列表的筛选和滚动位置，但重新进入时按数据新鲜度策略刷新。
- 编辑、发布、邀请和消息详情属于二级任务页，不显示一级入口以避免误触离开；返回前处理未保存状态。
- 所有深链使用页面 ID 和不透明资源 ID；只接受应用允许列表中的路径与参数。
- `401` 统一进入 `S-AUTH-01` 并记录安全的 `returnTo`；`403` 停留在当前上下文显示不可操作状态；`404` 与无权限响应按安全契约避免泄露。
- 项目发布成功后进入 `S-PROJ-03`，返回目标为 `S-PROJ-LIST-01`，不能回到仍可重复提交的发布确认态。
- 名片首次完成后返回原受保护目标；没有目标时进入 `S-ME-01`。

## 7. 状态与计数

- 一级入口的角标只用于需要处理的邀请或未读会话，不显示无法解释的“推荐红点”。
- “我的项目”按 `DRAFT/PUBLISHED/CLOSED` 分段或筛选，状态来自服务端，不由客户端时间推断。
- 草稿、私有名片、未公开联系方式和管理状态不得出现在公开搜索索引或页面预加载数据中。
- 空状态提供与当前页面目标一致的一个主要命令，例如“创建项目”或“完善名片”，不使用占位数据填充列表。
