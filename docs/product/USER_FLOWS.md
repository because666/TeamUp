## 1. 范围

本文定义首条 P0 纵向切片“微信登录 -> 建立能力名片 -> 创建并发布含开放岗位的项目”的用户可观察流程，以及恢复、失败和退出路径。需求依据为 `AUTH-001`、`PROF-001/002`、`PROJ-001`；页面 ID 见 [信息架构](INFORMATION_ARCHITECTURE.md)，字段和接口映射见 [页面规范](SCREEN_SPEC.md)。

本文不确认新的 API 或数据库字段。现有契约无法支持的步骤使用 `GAP-*` 登记，必须由角色 B 评审后才能进入公共契约。

## 2. 用户状态

| State | 含义 | 允许行为 |
| --- | --- | --- |
| `GUEST` | 尚未建立有效平台会话 | 查看条款与隐私说明、发起微信登录 |
| `AUTHENTICATED_PROFILE_INCOMPLETE` | 已登录，能力名片未达到首条切片最低要求 | 编辑名片；不能公开名片或发布项目 |
| `AUTHENTICATED` | 已登录且名片达到最低要求 | 浏览、编辑名片、创建项目草稿 |
| `PROJECT_DRAFT_OWNER` | 当前用户拥有未发布项目 | 编辑项目和岗位、预览、发布 |
| `PROJECT_PUBLISHED_OWNER` | 当前用户已成功发布项目 | 查看项目、继续管理或关闭项目 |
| `SESSION_EXPIRED` | 本地凭证存在但服务端已拒绝 | 清理本地会话并重新登录；保留可安全恢复的本地草稿 |

“名片完整”只表示满足产品字段校验，不代表履历已认证，也不自动把名片设为公开。

## 3. 主流程

### UF-AUTH-01：首次登录与同意

入口：首次启动、退出登录后进入、受保护页面发现无会话。

1. 客户端进入 `S-AUTH-01`，展示当前服务条款与隐私政策版本及链接。
2. 用户主动勾选同意。未勾选时登录命令不可执行。
3. 用户触发微信登录，客户端获取一次性凭证并调用 `API-AUTH-01`。
4. 提交期间保持固定页面结构、禁止重复提交，并显示进行中状态。
5. 登录成功后，客户端依据服务端返回的名片状态导航：未完成进入 `S-PROF-01`，已完成进入原目标页或“发现”。
6. 客户端只保存平台会话所需凭证，不保存微信一次性登录凭证。

失败与退出：

- 用户拒绝同意：保持 `GUEST`，不创建正式账号；仍可查看条款和隐私说明。
- 微信凭证获取失败、过期或已使用：显示可重试错误；重新获取凭证，不复用旧值。
- 网络失败：保持当前勾选状态，提供重试；不得伪造登录成功。
- 服务端 `401/403` 或同意版本失效：清理无效会话，回到可说明原因的登录状态。
- 用户关闭页面：不视为同意，不自动调用登录接口。

契约缺口：`GAP-AUTH-01`、`GAP-AUTH-02`，详见 [SCREEN_SPEC.md](SCREEN_SPEC.md#8-契约缺口清单)。

### UF-PROF-01：首次建立能力名片

前置：`AUTHENTICATED_PROFILE_INCOMPLETE`。

1. 客户端进入 `S-PROF-01`，调用 `API-PROF-01` 获取自己的完整名片。
2. 无既有名片时展示空表单；有部分资料时回填服务端确认的数据。
3. 用户填写基础信息、技能、经历、合作偏好和可投入时间。
4. 用户单独决定是否公开名片；默认不公开，不把“保存资料”等同于“公开资料”。
5. 客户端先执行长度、必填和枚举校验，再调用 `API-PROF-02`；服务端仍需执行完整校验和所有权判断。
6. 保存成功后更新本地版本号和完整状态，进入“我的”或登录前原目标页。

失败与退出：

- 首次加载失败：不展示伪造的空资料；提供重试和返回。
- 字段无效：聚焦首个错误字段，保留其余输入；错误摘要可被重复查看。
- `409` 版本冲突：不覆盖远程内容，提示重新加载并明确未保存修改会丢失。
- `401` 会话失效：保存安全的本地临时草稿，重新登录后由用户决定是否恢复。
- 离开未保存表单：弹出“继续编辑/放弃本次修改”；放弃只清除本地改动。
- 保存失败：保持表单内容和未保存标记，允许重试；不得显示完成状态。

契约缺口：`GAP-PROF-01`、`GAP-PROF-02`。

### UF-PROJ-01：创建草稿并发布项目

前置：`AUTHENTICATED`；当前用户是项目创建者。

1. 用户从“我的项目”或“发现”页创建入口进入 `S-PROJ-01`。
2. 客户端创建本地新草稿；首次显式保存时调用 `API-PROJ-01`，取得不透明 `projectId` 和 `version`。
3. 用户填写项目标题、简介、方向、适配赛事、阶段和团队信息。
4. 用户至少创建一个招募岗位，填写岗位名称、技能、人数、投入时间和说明。
5. 用户保存后进入 `S-PROJ-02` 预览。草稿仍不可出现在项目大厅或匹配结果中。
6. 客户端显示发布前缺失项；全部满足后，用户显式确认发布并调用 `API-PROJ-04`。
7. 发布成功进入 `S-PROJ-03`，展示服务端返回的 `PUBLISHED` 状态和发布时间，并提供查看项目/继续管理入口。

失败与退出：

- 草稿首次创建失败：保留本地输入，提供重试，不产生假 `projectId`。
- 后续保存失败：保留服务端最后成功版本和本地未保存标记。
- `409` 版本冲突：禁止静默覆盖，重新加载后由用户重新应用修改。
- 发布校验失败：回到对应字段或岗位，显示服务端稳定错误码映射的消息。
- 重复点击发布：客户端禁用命令；服务端仍须幂等或保证状态转换只成功一次。
- `403`：不隐藏错误，说明无权管理该项目并退出编辑态。
- 发布中断：重新进入时以服务端项目状态为准；若已发布，不重复发起发布。
- 离开未保存草稿：提示保存草稿/放弃本地修改/继续编辑。

契约缺口：`GAP-PROJ-01` 至 `GAP-PROJ-04`。

## 4. 纵向切片导航

```text
S-AUTH-01 登录与同意
  -> S-PROF-01 能力名片编辑
     -> S-ME-01 我的工作台
        -> S-PROJ-01 项目与岗位编辑
           -> S-PROJ-02 发布预览
              -> S-PROJ-03 发布结果/项目详情
```

返回规则：

- 登录前保存 `returnTo` 时只使用客户端允许列表中的页面 ID，不接受任意外部 URL。
- 登录后资料未完成时，先进入名片编辑；完成后再恢复 `returnTo`。
- 发布预览返回编辑页时保留当前草稿和滚动位置。
- 发布成功后系统返回键进入项目详情或我的项目，不重新提交发布。

## 5. 跨流程恢复

| 场景 | 恢复依据 | 用户看到的结果 |
| --- | --- | --- |
| 小程序被系统中断 | 服务端最后成功状态 + 本地非敏感草稿 | 询问是否恢复未保存输入 |
| 会话过期 | `401` 与本地目标页面 ID | 重新登录后恢复允许的目标页 |
| 保存响应丢失 | 重新 GET 资源及其 `version/status` | 以服务端结果判断是否已保存 |
| 发布响应丢失 | `API-PROJ-02` 返回的项目状态 | 已发布则进入成功/详情，草稿则允许重试 |
| 远端版本变化 | `409` 或版本不同 | 不自动覆盖，提示重新加载 |

本地恢复内容不得包含微信凭证、平台访问令牌、非公开第三方资料或服务端未授权数据。

## 6. 验收追踪

| Flow | PRD | 必验收结果 |
| --- | --- | --- |
| `UF-AUTH-01` | `AUTH-001` | 有效登录、拒绝同意、无效/过期凭证、网络失败、重复提交 |
| `UF-PROF-01` | `PROF-001/002` | 自有资料、字段校验、默认不公开、保存失败、版本冲突、未保存退出 |
| `UF-PROJ-01` | `PROJ-001` | 草稿不可见、开放岗位前置、仅 owner 管理、发布成功、重复发布和冲突 |

切片完成的产品证据必须同时包含正常路径，以及至少一次登录失败、名片校验失败、项目发布校验失败和会话/版本冲突处理。
