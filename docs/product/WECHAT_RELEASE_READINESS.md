# TeamUp 微信小程序主体、类目与发布准备

> Status: Proposed<br>
> Owner: 角色 A<br>
> Reviewers: 角色 B（技术、安全与部署）/ 正式发布前的合规负责人<br>
> Last Updated: 2026-08-16

## 1. 当前结论

当前个人主体后台展示的类目中，没有能够完整、准确覆盖 TeamUp P0 的选项。不得为了继续流程而将 TeamUp 申报为“教育信息展示”“工具-信息查询”或“商业服务-企业管理”。

TeamUp 当前允许用户建立公开能力名片、发布项目和岗位、浏览其他用户发布的项目，并发起联系方式交换或项目邀请。按照微信开放文档的适用范围，这一组合与非个人主体的“社交-社区/论坛”最接近，因为该类目覆盖 UGC 内容发布与交流。

正式选择仍为 `TBD`，必须以提交时微信后台显示的最新类目、主体条件和材料要求为准，并由发布合规负责人复核。

## 2. 为什么截图中没有合适类目

微信开放文档将“个人主体”和“非个人主体”的开放类目分开。当前截图中的“教育服务、交通服务、生活服务、旅游服务、工具、商业服务、体育”与官方个人主体列表一致；个人主体列表没有“社交-社区/论坛”。

| Candidate | 官方适用范围摘要 | 与 TeamUp 的结论 |
| --- | --- | --- |
| 个人主体：教育服务-教育信息展示 | 仅提供教育信息展示 | 不匹配；TeamUp 不是静态教育资讯展示 |
| 个人主体：工具-信息查询 | 提供信息查询功能 | 不匹配当前 P0；不能覆盖用户发布、公开访问与交流 |
| 个人主体：工具-办公 | 提供办公工具 | 不匹配；TeamUp 面向跨用户组队，不是单用户办公工具 |
| 非个人主体：社交-社区/论坛 | 提供 UGC 内容发布与交流，如论坛、贴吧、社群等 | 最接近当前 P0，仍需微信审核与合规确认 |
| 非个人主体：陌生人交友 | 陌生人关系中的即时沟通、互动、交友 | 不选择；TeamUp 已明确不是聊天或交友产品 |

## 3. 社区/论坛的已知要求

微信开放文档在 2026-08-15 显示，“社交-社区/论坛”适用于 UGC 内容发布与交流，并要求以下材料二选一：

1. 《非经营性互联网信息服务备案核准》；
2. 《统一社会信用代码证》（机构类型为机关，仅适用于政府主体）。

该类目首次提交代码审核还需要当地互联网主管机关审核确认。平台规则和材料名称可能变化，提交时必须再次核对官方后台，不得将本文当作法律意见或永久有效的材料清单。

## 4. 推荐推进方式

### 4.1 当前开发阶段

- 暂不选择不匹配的类目；类目不阻塞微信开发者工具导入和本地 fixture 验证。
- 当前个人 AppID 只用于开发验证，不承诺能够作为 TeamUp 正式商业发布主体。
- 在没有真实用户和生产数据前确定正式非个人主体与 AppID，避免后续 openid 命名空间和用户迁移成本。

### 4.2 正式发布阶段

- 使用符合要求的非个人主体账号，并重新核对是否能选择“社交-社区/论坛”；
- 准备小程序备案、微信认证、隐私保护指引、服务协议、UGC 审核、举报、拉黑、注销与数据删除能力；
- 按后台要求准备互联网信息服务相关备案或其他材料；
- 若继续使用个人主体，只能先重新裁剪产品范围，移除公开 UGC 与跨用户交流，再由平台确认“工具”类目是否适用；不能只改页面文案规避审核。

## 5. 与 CloudBase 和广告的关系

- 使用 CloudBase、自建服务器或域名不会自动改变可选类目；类目由主体、实际服务内容和平台规则决定。
- 接入广告不能解决主体或类目不匹配问题。正式接入广告前还要单独核对微信广告开通条件、未成年人保护、隐私披露、埋点和内容合规。
- 开发环境和正式主体若使用不同 AppID，微信 `openid` 不能直接视为同一用户标识；后端必须按 AppID 命名空间隔离。
